## 1. README — Обзор проекта

### О проекте

Лендинг для онлайн-продажи цветов с каталогом, фильтрацией, формой заказа и оплатой картой. Посетитель открывает сайт, выбирает букет, оформляет заказ за 2–3 минуты и оплачивает онлайн или при получении. Владелец магазина получает уведомление и отправляет доставку.

### Локальный запуск (для разработчика)

**Шаг 1. Клонирование репозитория**

Скопируйте проект на свой компьютер командой git clone. После этого перейдите в папку flower-shop.

**Шаг 2. Запуск бэкенда**

Перейдите в папку backend. Создайте виртуальное окружение командой python -m venv venv. Активируйте его — на Mac/Linux это source venv/bin/activate, на Windows — venv\Scripts\activate. Установите зависимости командой pip install -r requirements.txt.

Создайте файл .env, скопировав содержимое из .env.example. Заполните значения — минимум DATABASE_URL и STRIPE_SECRET_KEY (тестовый ключ).

Создайте таблицы и заполните базу данными: python seed_data.py

Запустите сервер: uvicorn main:app --reload --port 8000

Проверьте: откройте в браузере http://localhost:8000/docs — там будет интерактивная документация всех API-эндпоинтов.

**Шаг 3. Запуск фронтенда**

Откройте новый терминал. Перейдите в папку frontend. Установите зависимости командой npm install.

Создайте файл .env.local и добавьте две строки:

    VITE_API_URL=http://localhost:8000
    VITE_STRIPE_PUBLISHABLE_KEY=pk_test_ваш_тестовый_ключ

Запустите командой npm run dev. Сайт откроется на http://localhost:5173.

Добавьте переменные окружения в разделе Environment Variables — VITE_API_URL с адресом вашего бэкенда и VITE_STRIPE_PUBLISHABLE_KEY с боевым публичным ключом Stripe. Нажмите Deploy.

Зарегистрируйтесь на railway.app. Создайте новый проект из GitHub. Добавьте все переменные из .env.example с реальными значениями. Railway автоматически обнаружит Python-проект и запустит его. Скопируйте выданный URL — он станет вашим VITE_API_URL.

В переменной DATABASE_URL замените значение на:

    postgresql+asyncpg://пользователь:пароль@хост:5432/имя_базы

Больше ничего менять не нужно — остальной код уже готов к PostgreSQL.

## 2. API-документация

### Общие правила

Все запросы и ответы используют формат JSON. Базовый URL в продакшне: https://api.ваш-домен.ru. Все эндпоинты начинаются с /api/v1/. Ошибки возвращают понятное текстовое описание в поле detail.

**Коды ответов**

| Код | Значение |
|---|---|
| 200 | Успешный запрос |
| 201 | Объект создан |
| 400 | Ошибка валидации — неверные данные |
| 404 | Объект не найден |
| 422 | Данные не прошли проверку |
| 500 | Внутренняя ошибка сервера |

---

### Товары

**Получить список товаров**

    Метод:  GET
    Путь:   /api/v1/products

Параметры фильтрации (все необязательны):

| Параметр | Тип | Пример | Описание |
|---|---|---|---|
| category | строка | Романтика | Фильтр по поводу |
| max_price | число | 5000 | Максимальная цена в рублях |
| color | строка | Красный | Фильтр по цвету |
| size | строка | Средний | Фильтр по размеру |
| label | строка | ХИТ | Фильтр по метке |

Пример запроса с фильтрами:

    GET /api/v1/products?category=Романтика&max_price=4000

Пример ответа:

    {
      "total": 2,
      "items": [
        {
          "id": 1,
          "name": "Алые паруса",
          "label": "ХИТ",
          "description": "Классика, которая никогда не подводит...",
          "composition": "25 красных роз, зелень рускус...",
          "price": 3200,
          "category": "Романтика",
          "color": "Красный",
          "size": "Средний",
          "image": "https://..."
        }
      ]
    }

---

**Получить один товар**

    Метод:  GET
    Путь:   /api/v1/products/{id}

Пример: GET /api/v1/products/1

Возвращает полный объект товара. Если товар не найден — ответ 404 с текстом "Товар не найден".

### Заказы

**Создать заказ**

    Метод:  POST
    Путь:   /api/v1/orders

Тело запроса (все поля обязательны, кроме wishes):

| Поле | Тип | Пример | Описание |
|---|---|---|---|
| product_id | число | 1 | ID выбранного букета |
| name | строка | Иван Петров | Имя получателя |
| phone | строка | +79991234567 | Телефон получателя |
| address | строка | ул. Ленина, д.5, кв.12 | Адрес доставки |
| delivery_date | строка | 2024-12-25 | Дата в формате ГГГГ-ММ-ДД |
| delivery_time | строка | 14:00 | Время доставки |
| payment_method | строка | card или cash | Способ оплаты |
| wishes | строка | Открытка "Люблю тебя" | Необязательные пожелания |

Пример ответа при успехе (код 201):

    {
      "order_id": "ORD-2024-00142",
      "status": "pending",
      "payment_status": "pending",
      "total_amount": 3200,
      "message": "Заказ принят. Ожидайте подтверждения."
    }

Если выбрана оплата картой (card), после создания заказа фронтенд автоматически вызывает /api/v1/payments/create-intent с полученным order_id.

---

**Получить статус заказа**

    Метод:  GET
    Путь:   /api/v1/orders/{order_id}

Возможные значения поля status:

| Статус | Значение |
|---|---|
| pending | Принят, ожидает оплаты или подтверждения |
| confirmed | Подтверждён, готовится к доставке |
| delivering | Курьер в пути |
| delivered | Доставлен |
| cancelled | Отменён |

### Платежи

**Создать намерение оплаты**

    Метод:  POST
    Путь:   /api/v1/payments/create-intent

Тело запроса:

| Поле | Тип | Описание |
|---|---|---|
| order_id | строка | ID заказа, полученный при создании |
| amount | число | Сумма в рублях |

Пример ответа:

    {
      "client_secret": "pi_3OxH...secret_abc",
      "payment_intent_id": "pi_3OxH...",
      "publishable_key": "pk_live_..."
    }

client_secret передаётся в Stripe Elements на фронтенде для инициализации формы оплаты. Данные карты никогда не проходят через ваш сервер.

---

**Stripe Webhook (системный эндпоинт)**

    Метод:  POST
    Путь:   /api/v1/payments/webhook

Этот эндпоинт вызывает Stripe автоматически — не вы. Когда оплата проходит успешно, Stripe отправляет сюда уведомление, и система обновляет статус заказа на paid. Вам нужно только правильно его настроить (см. раздел 4).

## 3. Архитектура системы и база данных

### Как всё работает вместе

    Браузер пользователя
          │
          │ HTTPS-запросы
          ▼
    ┌─────────────────┐
    │   React-сайт    │  ← Статические файлы на Vercel/Netlify
    │  (Frontend)     │    Только HTML, CSS, JS — никаких секретов
    └────────┬────────┘
             │ API-запросы к /api/v1/
             ▼
    ┌─────────────────┐
    │  FastAPI-сервер │  ← Бизнес-логика, валидация, хранение данных
    │   (Backend)     │
    └────────┬────────┘
             │
       ┌─────┴──────┐
       ▼            ▼
    ┌──────┐   ┌─────────┐
    │  БД  │   │ Stripe  │  ← Платёжный шлюз, данные карт хранятся там
    │SQLite│   │  API    │
    │ или  │   └─────────┘

    └──────┘

### Поток данных при оформлении заказа

    1. Пользователь заполняет форму на сайте
         ↓
    2. Фронтенд валидирует поля (имя, телефон, адрес)
         ↓
    3. POST /api/v1/orders → бэкенд создаёт запись в БД
         ↓
    4а. Если оплата наличными → статус pending_cash
         → Уведомление владельцу (SMS/email)
         → Заказ завершён
         
    4б. Если оплата картой → POST /api/v1/payments/create-intent
         → Stripe возвращает client_secret
         → Фронтенд рендерит Stripe Elements
         → Пользователь вводит карту
         → Stripe обрабатывает оплату
         → Stripe отправляет webhook на /api/v1/payments/webhook
         → Бэкенд обновляет payment_status = paid
         → Уведомление владельцу
         → Редирект на страницу успеха

## 4. Настройка платёжной интеграции Stripe

### Что такое Stripe и зачем он нужен

Stripe — международный платёжный сервис. Он принимает оплату картой вместо вас, соблюдает все требования безопасности и переводит деньги на ваш счёт. Вы не храните данные карт — это делает Stripe.

---

### Шаг 1. Регистрация в Stripe

Зайдите на stripe.com и создайте аккаунт. Для тестирования регистрация с российским телефоном работает. Для приёма реальных платежей потребуется верификация бизнеса.

В личном кабинете Stripe перейдите в раздел Developers → API keys. Вы увидите два ключа:

| Ключ | Начинается с | Где используется |
|---|---|---|
| Publishable key | pk_test_ или pk_live_ | На фронтенде (публичный, не секретный) |
| Secret key | sk_test_ или sk_live_ | На бэкенде (секретный, никому не показывать) |

Для тестирования используйте ключи с test. Для продакшна — с live.

---

### Шаг 2. Добавление ключей в проект

В файле backend/.env добавьте или обновите строки:

    STRIPE_SECRET_KEY=sk_test_ваш_секретный_ключ
    STRIPE_WEBHOOK_SECRET=whsec_ваш_ключ_вебхука  ← настроим в следующем шаге

В файле frontend/.env.local:

    VITE_STRIPE_PUBLISHABLE_KEY=pk_test_ваш_публичный_ключ

Никогда не коммитьте файлы .env и .env.local в Git. Они добавлены в .gitignore, но убедитесь в этом дополнительно.

---

### Шаг 3. Настройка Webhook

Webhook — это механизм, которым Stripe сообщает вашему серверу об успешной оплате. Без него ваш сервер не узнает, что платёж прошёл.

**Для разработки (локально)**

Установите Stripe CLI, следуя инструкции на stripe.com/docs/stripe-cli. После установки выполните:

    stripe login
    stripe listen --forward-to localhost:8000/api/v1/payments/webhook

Stripe CLI покажет вам webhook-ключ в формате whsec_.... Скопируйте его в STRIPE_WEBHOOK_SECRET в файле .env.

**Для продакшна**

В личном кабинете Stripe перейдите в Developers → Webhooks → Add endpoint. В поле Endpoint URL введите адрес вашего сервера:

    https://api.ваш-домен.ru/api/v1/payments/webhook

В разделе Select events выберите следующие события:

| Событие | Что происходит |
|---|---|
| payment_intent.succeeded | Оплата прошла успешно |
| payment_intent.payment_failed | Оплата не прошла |
| charge.refunded | Возврат средств |

Сохраните. Stripe покажет Signing secret для этого endpoint — это и есть ваш STRIPE_WEBHOOK_SECRET.

### Шаг 4. Тестовые карты

При разработке используйте тестовые данные карт от Stripe. Реальные деньги не списываются.

## 5. Юридические документы

### Обзор документов

На сайте размещены четыре юридических документа, которые защищают вас как продавца и информируют покупателей об их правах.

| Документ | Где хранится | Где отображается |
|---|---|---|
| Публичная оферта | docs/legal/offer.md | Ссылка в футере, чекбокс в форме |
| Политика конфиденциальности | docs/legal/privacy.md | Ссылка в футере, чекбокс в форме |
| Согласие на обработку данных | Встроено в компонент OrderForm.tsx | Чекбокс под формой заказа |
| Cookie-политика | docs/legal/cookies.md | Баннер при первом посещении |

---

### Где документы подключены в коде

**Форма заказа (OrderForm.tsx)**

Под кнопкой "Оформить заказ" есть обязательный чекбокс. Без его отметки кнопка неактивна. Текст чекбокса содержит ссылки на Оферту и Политику конфиденциальности. Это реализует требование закона о явном согласии пользователя.

**Футер (Footer.tsx)**

В подвале сайта размещены текстовые ссылки на все документы. Они открываются в новой вкладке (/legal/offer, /legal/privacy, /legal/cookies).

**Cookie-баннер (App.tsx)**

При первом визите появляется баннер с кратким описанием использования cookie и кнопками "Принять" и "Подробнее". Статус согласия сохраняется в localStorage, чтобы баннер не показывался при следующих визитах.
